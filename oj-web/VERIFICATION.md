# 初版验收记录

## 2026-11-19 修复：登录成功后提示用户不存在

- 真实服务复现：直连系统服务与经前端开发代理时，`POST /sysUser/login` 都返回 1000，随后 `GET /sysUser/info` 返回 3102。不是账号密码错误，也不是数据库缺少管理员。
- 根因：系统服务默认组件扫描范围为 `com.amadeus.system`；公共安全模块的自动装配清单只注册了异常处理器和 TokenService，遗漏 TokenInterceptor 与 WebMvcConfig。仅声明 `@Component` 或 `@Configuration` 不会使扫描范围外的类自动生效。
- 结果：受保护接口未经过拦截器，当前请求上下文没有 userId，查询用户时返回用户不存在；注销也因缺少 userKey 而无法撤销会话。
- 修复：在安全模块的 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 补齐拦截器及 MVC 注册配置，不改数据库记录或登录密码。
- 新增自动装配回归测试：从实际模块清单加载配置，而不是手动注册拦截器，覆盖未登录访问 info/logout 返回 401、登录保持放行，以及 JWT 中的用户 ID 正确传递给 Controller。
- 验证结果：修复前，自动装配测试明确报告缺少 WebMvcConfig；修复后，2 项自动装配测试、14 项退出测试及 20 项基于隔离 MySQL/Redis 容器的集成测试全部通过，共 36 项。测试未修改开发数据库中的管理员记录。
- 部署注意：重新构建并重启系统服务 `OjSystemApplication` 才会加载新的自动装配清单；仅刷新网页不会让运行中的 Spring 容器重新注册拦截器。

## 2026-11-19 续接：服务端退出登录

- 新增受保护的 `POST /sysUser/logout`；请求头携带 Bearer Token，无需请求体。由现有拦截器校验 JWT 与 Redis 会话，Controller 从当前请求上下文读取已验证的 `userKey`，再删除对应的 `logintoken:<userKey>`。
- 注销只影响当前会话，不删除同账号的其他登录会话。已注销或未登录的请求返回 HTTP 401；鉴权后 Redis 会话恰好失效、删除返回 false 时返回业务码 3001。Redis 异常返回失败，不伪装成功。
- 前端退出按钮已接入真实接口，等待服务器成功后再清理本地会话；请求期间防重复提交，网络及服务异常显示重试提示，旧退出请求不会清除新登录会话。
- 后端定向测试 `SysUserLogoutTest` 共 14 项全部通过：使用实际 JWT、拦截器、Controller、Service 与模拟 Redis，覆盖撤销、旧 Token 重用、重复退出、无效签名、会话隔离、删除失败及上下文清理。
- 前端生产构建（包含 TypeScript 检查）通过；实际 Vue/Pinia 配合模拟接口的临时回归检查覆盖无会话退出、等待服务器、成功清理、失败保留、新会话竞态及未授权清理，均通过。
- 已在现有 Testcontainers 集成测试中新增真实 Redis 撤销验证用例，测试代码编译通过；本轮未执行容器集成测试，不能将模拟 Redis 的测试结果等同于真实服务联调通过。

项目根目录可运行不依赖 Docker 的定向测试：

```powershell
mvn -pl oj-modules/oj-system -am test '-Dtest=SysUserLogoutTest' '-Dsurefire.failIfNoSpecifiedTests=false'
```
